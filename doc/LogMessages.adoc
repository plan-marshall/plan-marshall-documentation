= Log Messages
:toc: left
:toclevels: 2
:nofooter:

All messages are defined in `de.planmarshall.core.log.PmMcpLogMessages` (module `pm-core`) with prefix `PM_MCP`; every module logs through it, today the classes of `pm-core`, of `pm-runtime` and of the assembly `pm-mcp-server`.
Identifier ranges: INFO 001-099, WARN 100-199, ERROR 200-299.

== INFO Level (001-099)

[cols="1,1,2,2", options="header"]
|===
|ID |Component |Message |Description
|PM_MCP-1 |HelloTool |Hello tool invoked for '%s' |Logged when the `hello` MCP tool is called
|PM_MCP-10 |SocketBinding |Runtime ready on socket '%s' (pid %s) |Logged when the Unix socket is bound, restricted to mode `0600` and recorded in `state/runtime.json` (startup step 7)
|PM_MCP-11 |WebListener |Web listener open on %s:%s (lan: %s) |Logged when the web listener has opened on its address and port
|PM_MCP-12 |WebListener |Web listener on port %s closed |Logged when the web listener has closed (web access disabled, or the runtime stops)
|PM_MCP-13 |RuntimeApiResource |Runtime stop requested through the local API |Logged when `POST /api/v1/runtime/stop` is accepted; the runtime exits with code `0` shortly after
|PM_MCP-14 |CoreTools |Core tools registered: %s |Logged at start with the core tools registered with their flat input schemas
|PM_MCP-15 |WebListener |Web listener open requested on %s:%s (lan: %s), cause: %s |Logged for every request to open the web listener, also one that finds it open, with the address, the requested port (`0` for any free port), the exposure and what asked for it (`PUT /api/v1/web`)
|PM_MCP-17 |WebListener |Web listener on port %s closing, cause: %s |Logged before the web listener closes, with what caused the close (`PUT /api/v1/web` or `runtime shutdown`)
|PM_MCP-30 |SecretStoreProducer |Credential store '%s' active, service name '%s' |Logged at start with the one active credential backend (`keychain`, `secret-service` or `file`) and the keyring service name of the instance
|PM_MCP-40 |LspClient |Language server '%s' started (pid %s, position encoding %s) |Logged when a language server of the LSP pool answered `initialize`; names the executable, its process id and the negotiated position encoding
|PM_MCP-50 |StaleLeaseSweep |Stale lease sweep of '%s' finished: %s kept, %s orphaned, %s removed |Logged when the stale lease sweep of a lease store has finished, with the store and how many leases it kept, marked orphaned and removed
|PM_MCP-51 |ServiceUnitInstaller |Service unit '%s' installed for daemon '%s' |Logged when `pm-operator runtime install` has written the per-user service unit and the service manager has loaded it; names the unit file and the daemon it starts
|PM_MCP-52 |ServiceUnitInstaller |Service unit '%s' uninstalled |Logged when `pm-operator runtime uninstall` has removed the per-user service unit and the service manager has unloaded it, also when no unit was present; names the unit file. Not logged when the unload ended the runtime that the service had started
|PM_MCP-60 |Enrolments |Enrolment of project '%s' written (pilot: %s) |Logged when `enrol` has written a project's enrolment file and its sidecar record under the project's enrolment lock; names the project and whether it was enrolled as a pilot of the lifecycle gate. Its `enrolment_written` audit record was owed in `enrolments/<project_id>.json.audit-intent` before the write as an unconfirmed record, confirmed after the write and handed over, or stays owed there (`PM_MCP-160`, `PM_MCP-164`)
|PM_MCP-61 |Enrolments |Enrolment of project '%s' removed, its project store kept |Logged when `unenrol` has removed a project's enrolment file and its sidecar; the project's machine store below `projects/<project_id>/` is untouched. Not logged when the project had no enrolment. Its `enrolment_removed` audit record was owed in `enrolments/<project_id>.json.audit-intent` before the removal as an unconfirmed record, confirmed after the removal and handed over, or stays owed there (`PM_MCP-160`, `PM_MCP-164`)
|PM_MCP-62 |Enrolments |Enrolment of project '%s' re-baselined |Logged when the re-baseline of `accept-edit enrolment` has rewritten the sidecar record of a project's enrolment file over its current bytes. Its `enrolment_rebaselined` audit record was owed in `enrolments/<project_id>.json.audit-intent` before the write as an unconfirmed record, confirmed after the write and handed over, or stays owed there (`PM_MCP-160`, `PM_MCP-164`)
|PM_MCP-63 |Enrolments |Owed audit record '%s' of transaction '%s' for project '%s' handed over after an earlier refusal or stop |Logged when a record that an earlier enrolment write owed (its hand-over was refused or stopped) is handed over by a later enrolment operation or by the recovery sweep (`Enrolments.replayOwedAudit()`); names the event, its transaction id and the project. A record handed over again after a stop carries the same transaction id, by which the audit store drops the duplicate. An unconfirmed record (outcome `failed`) handed over this way is logged `PM_MCP-164` as well
|===

== WARN Level (100-199)

[cols="1,1,2,2", options="header"]
|===
|ID |Component |Message |Description
|PM_MCP-110 |SocketBinding |Socket '%s' had mode %s after the bind and was set to 0600 |Logged when Vert.x created the socket under the process umask; the runtime restricts it right after the bind
|PM_MCP-111 |CoreTools |Core tool '%s' not registered: the name is already registered |Logged when another component registered a core tool name first
|PM_MCP-112 |WebListener |Web listener could not open on port %s: %s |Logged when the web listener cannot bind its port (answered `web_listener_conflict`), for each candidate port it rejects while choosing a port for port `0`, or when it cannot close cleanly
|PM_MCP-113 |WebListener |Web listener on port %s: connection failed before a request (TLS handshake or connection setup): %s |Logged when a connection to the web listener fails before its first request, a failed TLS handshake included; one line with the class and message of the failure and no stack trace, since a client can cause it at will
|PM_MCP-130 |SecretStoreProducer |No OS keyring usable, the file credential store serves: %s |Logged at start when neither the macOS Keychain nor the Secret Service is usable; the reason names the backend and why
|PM_MCP-140 |LspClient |Language server (pid %s) did not end cleanly, terminating it: %s |Logged when `shutdown`/`exit` fails or the process does not end within the request timeout; the process is then terminated
|PM_MCP-150 |WorkspaceConfinement |Project path refused with outcome '%s': %s |Logged when a project path is refused by the workspace confinement (`PM-SEC-2`); names the outcome code `path_traversal_rejected` and the reason of the refusal (`UNPARSEABLE_PATH`, `PARENT_NAME_AFTER_MISSING_PART`, `CANONICALIZATION_FAILED` or `OUTSIDE_WORKSPACE`), never the path
|PM_MCP-151 |StaleLeaseSweep |Lease '%s' in '%s' orphaned: its holder (pid %s) is no longer alive |Logged for each lease the stale lease sweep marks orphaned because the runtime that served it is no longer alive; names the lease key, the lease store and the process id of the dead holder
|PM_MCP-160 |OwedAuditEvents |Audit record '%s' of transaction '%s' not handed over, kept owed in '%s': %s |Logged when the audit sink refuses the record of a completed store mutation (a roll-forward, a JSONL tail repair, a reconciliation or an enrolment write); names the event, its transaction id and the durable intent that keeps it owed (the transaction journal, `<store>.audit-intent`, or for an enrolment write `enrolments/<project_id>.json.audit-intent`). The data outcome is unchanged, and the next recovery or repair, or for an enrolment write the next enrolment operation of the project or `Enrolments.replayOwedAudit()`, hands the record over again
|PM_MCP-161 |EnrolmentCheck |Enrolment of project '%s' refused with outcome 'enrolment_tampered': %s |Logged when the enrolment check refuses a project's enrolment because it does not match its sidecar record; names the project and the reason (`size or SHA-256 differs from the sidecar record`, `HMAC differs from the sidecar record`, `the integrity key does not exist`, `sidecar without its enrolment file`, `enrolment file without its sidecar`), never the key or an HMAC. Only that project is blocked; an `enrolment_tampered` audit record follows
|PM_MCP-162 |EnrolmentCheck |Enrolment of project '%s' refused with outcome 'enrolment_insecure': %s |Logged when a project's enrolment file or its sidecar fails a per-use check; names the project and the reason (a symbolic link, a foreign owner, a mode broader than `0600`). Only that project is blocked, never the runtime start; an `enrolment_insecure` audit record follows
|PM_MCP-163 |Enrolments |Unenrol of project '%s' refused with outcome 'scope_active', live work: %s |Logged when `unenrol` is refused because the project has live work; names the project and every item of it (`plan <plan_id>`, `epic <epic_id>`, `job <job_id>`). Nothing is removed; an `unenrol_refused` audit record follows
|PM_MCP-164 |Enrolments |Audit record '%s' of transaction '%s' for project '%s' handed over as not confirmed: the write did not complete or its completion was not recorded |Logged when the owed audit record of an enrolment write that was started and not confirmed complete is handed over: the mutation failed, or the process stopped before or after it took effect. The record is handed over by a later enrolment operation of the project or `Enrolments.replayOwedAudit()` as outcome `failed` with the reason `not_confirmed`; the message names the event, its transaction id and the project. The record is never handed over as `succeeded`. The enrolment file and its sidecar show what became of the write (link:concepts/store-integrity.adoc#audit-delivery[Concepts § Store Integrity, Audit Records of a Store Change])
|===

== ERROR Level (200-299)

[cols="1,1,2,2", options="header"]
|===
|ID |Component |Message |Description
|PM_MCP-210 |SocketBinding |Socket '%s' could not be secured or recorded, exiting with code 77 |Logged when the bound socket cannot be set to mode `0600` or `state/runtime.json` cannot be written; the runtime exits with code `77`
|PM_MCP-230 |CredentialsResource |Credential store '%s' failed: %s |Logged when a request of `/api/v1/credentials/{key}` fails in the backend (locked keyring, insecure or invalid credential file, keyring error); never contains the secret
|PM_MCP-250 |FileLockManager |Lock order violation: '%s' requested while holding %s |Logged when a lock is requested against the total lock order; the request is refused with the internal fault `lock_order_violation`, nothing is acquired, and a `lock_order_violation` audit record is written
|PM_MCP-251 |ServiceUnitInstaller |Service manager command '%s' failed: %s |Logged when a step of the service manager fails during install or uninstall of the per-user service unit; names the step (`load`, `disable` or `unload`) and the failure (the command with its exit code and output, or why it could not run), never an environment value; the failure is reported to the caller
|PM_MCP-260 |EnrolmentKey |Enrolment integrity key unavailable from '%s': %s |Logged when the enrolment integrity key exists and cannot be read, or cannot be created: an insecure or malformed key file, or a failing credential store; names the source (the key file `state/enrolment-hmac.key`, or the credential store with the account `enrolment-integrity-key`) and the reason code, never the key. The read or the write that needed the key fails
|===
