This is not a summary of the tools. It keeps what is useful for PM-MCP and says where it touches our documents.

== What They Do

They show remaining quota and the next reset, so that an operator does not start a large task just before a limit.
They save no tokens. UsageScope signs in with OAuth and asks the provider; ccusage parses the harness's local session
logs (`~/.claude/projects/`) into reports per session.

== Where It Touches Our Documents

=== Our own records are the instrument

PM-MCP parses the usage of every turn from the harness output, through the client profile's usage declaration, and
attributes it to task, role, phase and plan, with every figure either measured, unmeasured, or not applicable
(xref:../Requirements.adoc#PM-WF-14[PM-WF-14], xref:../Requirements.adoc#PM-CLIENT-2[PM-CLIENT-2]). A quota meter adds
convenience for the operator, not a capability.

=== Quota is a fact the operator would want before a plan

Usage is recorded and never limits a plan
(link:https://github.com/plan-marshall/pm-mcp-core/blob/main/doc/specification/model-work/09-completion-usage-and-spend.adoc[Model Work, Completion, Usage & Spend]).
How much of the harness's quota is left, and when it resets, is a fact the operator might want before starting an
epic, but it is the provider's, not ours. Nothing to change.

=== Cross-check the instrument against an independent count

Our usage figures and a log parser such as ccusage read the same underlying records through different code.
Agreement over a matched, fully covered window is evidence that our parsing counts completely; disagreement there is
a defect in one of the two. The comparison is only meaningful once the populations match:

* the same window: our per-task figures cover a worker's turns, while a session log may hold more than one task of a
  warm worker, or the turns of a session we did not start;
* the same fields: input, output, cache read and cache creation, one by one;
* no partial field: an unmeasured figure is not a zero (our records keep them apart), so it is excluded, not summed.

Our workers run in a per-worker data directory where the client profile declares one, so the harness's own session
logs of a worker can be found by the worker's job.
