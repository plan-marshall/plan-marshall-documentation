This directory holds one analysis per external article, paper or repository: what in it is useful for PM-MCP, and
where it touches our requirements and specifications. It is not a summary of the source; the source is linked. Nothing
here is part of the target design unless a requirement or specification adopts it. Each analysis reflects the source
when it was read; recheck the source before relying on it.

A paper or repository behind an article gets its own analysis named `<article>-<source>.adoc`, linked from the
article's analysis. A source that several articles cite gets one analysis under its own name.

* xref:clean-code-to-clean-spec.adoc[Clean Code to Clean Spec] — spec-driven development, the six elements of a spec,
  clean code as token cost for agents.
** xref:clean-code-to-clean-spec-cleanliness-study.adoc[Cleanliness study] (arXiv:2605.20049) — measured agent footprint
   on clean versus messy repositories; a method for measuring skill changes.
** xref:clean-code-to-clean-spec-aposd-debate.adoc[APOSD vs. Clean Code] — over-decomposition, interface comments,
   TDD versus bundling, read against our pipeline.
* xref:karpathy-ste100-output.adoc[ASD-STE100 Output] — one writing rule for every agent whose text a human reads;
  diagrams instead of text.
