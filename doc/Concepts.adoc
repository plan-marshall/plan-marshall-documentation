== Overview

The concepts explain *why* `PM-MCP` is built the way it is and *what* its parts are, in principle. They define nothing: the normative statements are in the link:Requirements.adoc[Requirements] and the link:Specification.adoc[Specification], which each concept links for its details. A concept of the implemented system is written from the specification when the system is built.

== Concepts

[cols="1,3", options="header"]
|===
|Concept |What it explains

|link:concepts/harness-as-worker/README.adoc[Harness as Worker]
|`PM-MCP` drives plans and epics; harness processes with their models are supervised workers that the server starts, offers tasks, watches, and replaces. The journey from plan-marshall to this design, the architecture, the task protocol, roles as configuration, and the delivery of skills.

|link:concepts/locks-and-leases.adoc[Locks and Leases]
|How the runtime keeps concurrent writes from losing each other or deadlocking: short locks in one total order, lock files beside the stores, reads without locks, and leases for claims that last longer than a transaction.

|link:concepts/store-integrity.adoc[Store Integrity]
|How the stores stay trustworthy: exactly one format version accepted and every other refused, the transaction journal that makes a write of several stores survive a crash, writes across scopes in a fixed order, append-only logs with their torn tail repaired, and digests that reveal an edit made outside the runtime.
|===
