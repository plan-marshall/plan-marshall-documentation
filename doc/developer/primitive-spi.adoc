[#spi-contract]
== The Contract of a Primitive
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5], link:../Requirements.adoc#PM-ARCH-4[PM-ARCH-4]_

A primitive is one deterministic operation of the server. Its contract is the package `de.planmarshall.core.spi` of the module `pm-core` in the repository https://github.com/plan-marshall/pm-mcp-core[`pm-mcp-core`]. The package holds the contract and the registry only; it holds no primitive. A primitive is stateless, so one instance serves every call.

[cols="1,3", options="header"]
|===
|Type |What it is

|{spi}/Primitive.java[`Primitive<P, R>`]
|The operation: its canonical name, the record class `P` of its parameters, the enum class `R` of its outcomes, the method `execute`, and the declarations of what it does beyond returning an outcome.

|{spi}/PrimitiveOutcome.java[`PrimitiveOutcome`]
|One outcome. The outcomes of a primitive are the constants of one enum that implements this interface, so the set is closed. An outcome has a wire name, by which a workflow routes it, and an outcome class.

|{spi}/OutcomeClass.java[`OutcomeClass`]
|The classes an outcome can have. The class of an outcome, never its wire name, decides how the outcome is recorded.

|{spi}/PrimitiveResult.java[`PrimitiveResult<R>`]
|What one execution returns: the outcome, the facts it changed, and the identifier of the job it started, if any.

|{spi}/WorkflowExecutionContext.java[`WorkflowExecutionContext`]
|What a primitive is handed for one execution: the scope the call addresses.

|{spi}/AwaitedEvent.java[`AwaitedEvent`]
|The external events a primitive can wait for before its outcome can change.

|{spi}/CycleMeasure.java[`CycleMeasure`]
|The finite measures that can end a cycle through the state of a primitive.

|{spi}/FreeParam.java[`@FreeParam`]
|Marks a component of a parameter record as a value the caller supplies and declares the length bounds of a text value.
|===

The constants of the enums are stated in their sources and nowhere else; read them there.

=== What a Primitive Declares

`id()`, `parameterType()`, `outcomeType()`, `execute(…)` and `awaitedEvent()` have no default, so no primitive compiles without them. A primitive whose outcome depends only on what it reads in the same call declares the awaited event `NONE`.

The other declarations have a default that says "nothing":

* `producedArtifacts()` and `requiredArtifacts()` name the artifacts the primitive produces as side effects and the ones that must exist before it can pass.
* `waivableGates()` names the gates the primitive may look a waiver up for. A primitive never writes a waiver.
* `enqueuesJob()` is `true` for a primitive that starts a job. Such a primitive has at least one outcome whose `startsJob()` is `true` and reports the job in `PrimitiveResult.spawnedJobId()`.
* `cycleMeasure()` names the measure that strictly decreases on every pass of a chained cycle through the state of the primitive. A primitive with the measure `ATTEMPT_CAP` also declares `exhaustionOutcome()`: the wire name of the outcome it returns once its cap is spent.

=== The Result

`PrimitiveResult` refuses a `null` component, a fact without a name and a fact without a value with a `NullPointerException`. It keeps an unmodifiable copy of the facts in the order they were passed, so a later change of the map a primitive handed over does not reach the result.

=== The Scope of a Call

`WorkflowExecutionContext.scopeId()` returns the identifier of the plan or epic the call addresses. For the workspace scope of a project, which has no identifier of its own, it returns an empty `Optional`. The reserved value a caller addresses the workspace scope with is never returned, so a primitive cannot take it for the identifier of a plan. The context reads and writes no store.

[#registry]
== The Registry
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5]_

{spi}/PrimitiveRegistry.java[`PrimitiveRegistry`] holds the primitives of one assembly by id. It is filled through its constructor and by nothing else: the assembly passes its primitives, a test passes the ones it needs. The registry looks nothing up on the classpath, and there is no second place where a primitive is switched on. A primitive that is not passed to the constructor does not exist for the registry.

`find(id)` returns the primitive with an id, or an empty `Optional`; `ids()` returns the ids in the order the primitives were passed.

=== What the Constructor Refuses

The constructor checks every primitive before the registry exists. One malformed primitive leaves no registry at all; the constructor throws a {spi}/PrimitiveRegistrationException.java[`PrimitiveRegistrationException`] for the first primitive it refuses, in the order of the argument. The exception carries the id of the primitive and a `Reason`; tell refusals apart by the reason, never by the message. The reasons are the constants of `PrimitiveRegistrationException.Reason`, each documented at its constant.

The constructor checks what the declarations of a primitive decide on their own:

* The id is two identifiers joined by a dot. An identifier starts with a lower-case letter, followed by at most 31 lower-case letters, digits, `_` or `-`. No two primitives have the same id.
* The parameter type is a record class.
* The outcome type is an enum that implements `PrimitiveOutcome` and has at least one constant.
* Every wire name is an identifier of the form above, no two outcomes of a primitive share one, and none is `stepped_out`, the name of the control outcome that only the engine returns when a sub-workflow is left.
* The job side effect is declared on both sides: a primitive that enqueues a job has a job-starting outcome, and a primitive with a job-starting outcome declares that it enqueues a job.
* A primitive with the measure `ATTEMPT_CAP` names an exhaustion outcome that is one of its outcomes and has the class `FAILURE`.
* The awaited event is not `null`.

A `null` collection or element is a `NullPointerException`, not a refusal.

The constructor does not check what needs more than the primitive itself: whether a declared gate is on the list of waivable gates, whether a produced artifact is required by anyone, whether a name collides with a keyword of the workflow language, and whether an execution that returns a job-starting outcome carries a job identifier. `@FreeParam` is a declaration only; nothing in `pm-core` reads it.

[#content-validators]
== The Content Validators
_Requirements: link:../Requirements.adoc#PM-WF-6[PM-WF-6]_

A content validator checks a text that a model submitted against the rules of its kind. The contract and the three validators are the package https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-core/src/main/java/de/planmarshall/core/spi/validation[`de.planmarshall.core.spi.validation`].

{spi}/validation/ContentValidator.java[`ContentValidator`] has one method, `validate(String)`. A validator is stateless and reads nothing but its argument. A text it rejects is an answer, not a failure: the violations are returned in the order of their lines, never thrown, and an accepted text returns an empty list. Only a `null` text is an exception.

A {spi}/validation/ContentViolation.java[`ContentViolation`] names the rule by a stable key, the line counted from 1 (`0` when the violation concerns the whole text), and a message that quotes the offending content. A caller tells violations apart by the key, never by the message. The keys are the public `RULE_*` constants of each validator, each documented at its constant.

Every validator rejects a blank text. Beyond that:

[cols="1,3", options="header"]
|===
|Validator |What it rejects

|{spi}/validation/ConventionalCommitValidator.java[`ConventionalCommitValidator`]
|A first line that is not of the form `type(scope)!: description` (the scope and the `!` are optional, the type consists of letters, and one space follows the colon), a header without a type or without a description, a body that does not start on the third line after exactly one blank line, and every `Co-Authored-By:` line, wherever it stands, in any spelling of upper and lower case, and whatever it names.

|{spi}/validation/AsciiDocValidator.java[`AsciiDocValidator`]
|A control character other than a tab, a delimited block that is never closed, a document title that is not the first non-blank line, a second document title, and a section more than one level below the section before it. A line inside a delimited block is content: it is neither a title nor a section, and inside a listing, literal or passthrough block it opens no further block.

|{spi}/validation/OutlineValidator.java[`OutlineValidator`]
|In a list below `+**Affected files:**+`: a line that is not a bullet starting with a back-quoted path, and a path without one of the intents `(read)`, `(write-new)`, `(write-replace)`, `(write-conditional)`, `(delete)` at the end of its line. In a list below `+**Added dependencies:**+`: a line that is not a bullet with exactly one back-quoted coordinate, an ecosystem other than `maven`, `npm` and `pypi`, a coordinate that is not of the form of its ecosystem (for example because it carries a version), and a coordinate named a second time anywhere in the outline.
|===

Three properties of the validators are deliberate:

* *A trailer in the submitted message is refused even when it equals the one the server would write.* The server appends the trailer it resolved itself; accepting one from the text would let the text of a model decide whom a commit credits.
* *A line of a list that does not parse is a violation, never skipped.* `OutlineValidator` reads each of the two lists from its marker line to the next line that starts with `+**+` or `+#+`. A bullet with a typing error therefore surfaces with its line number instead of silently dropping an entry from the list.
* *A coordinate has the name form of its ecosystem.* A Maven coordinate is `maven:<groupId>:<artifactId>`, both parts of letters, digits, `_`, `.` and `-`. An npm coordinate is `npm:<name>` in lower case, optionally with a scope (`npm:@scope/name`). A Python coordinate is `pypi:<name>`, starting and ending with a letter or digit; two Python names are the same name when they differ only in case or in their runs of `-`, `_` and `.`.

`OutlineValidator` decides only what the text decides on its own. It does not check that the files exist, that the tasks of the outline can be derived, or that a deliverable declares what its files require.

[#pitfalls]
== Pitfalls
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5], link:../Requirements.adoc#PM-WF-6[PM-WF-6], link:../Requirements.adoc#PM-ARCH-4[PM-ARCH-4]_

* *Give an outcome the class of what happened, not of how it sounds.* An operation of several parts of which one failed returns an outcome of class `FAILURE`. The class reaches the caller unchanged through `execute`, and a caller reads the class, never the wire name.
* *Declare the awaited event that is true.* `NONE` is right only for a primitive whose outcome cannot change without a new call. A primitive that looks at a provider, a remote or the checkout again waits for an event.
* *An attempt cap ends in a failure.* The exhaustion outcome of a primitive with `ATTEMPT_CAP` has the class `FAILURE`; the registry refuses any other class.
* *Do not treat the workspace scope as a plan.* An empty `scopeId()` is the workspace scope. Do not replace it by a placeholder identifier.
* *Do not copy a closed vocabulary.* The outcome classes, the awaited events, the cycle measures, the refusal reasons and the rule keys each have one Java source. Link the type; a copied list is wrong after the next change.
* *A rule without a rejected case is not tested.* Every rule key of a validator has a test case with a text that breaks exactly that rule and asserts the key and the line.

[#extending]
== Adding a Primitive or a Validator
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5], link:../Requirements.adoc#PM-WF-6[PM-WF-6]_

A new primitive:

. Write the parameter record and the outcome enum. The enum implements `PrimitiveOutcome`; give every constant its wire name and its class.
. Implement `Primitive<P, R>` in the module the operation belongs to, and override a declaration only where the default "nothing" is not true.
. Pass the instance to the constructor of the `PrimitiveRegistry` of the assembly.
. Test it without a framework: construct a `PrimitiveRegistry` with it, which proves that it is well formed, and call `execute` with a `WorkflowExecutionContext` the test writes itself (the interface has one method).

{spi-test}/TestPrimitives.java[`TestPrimitives`] holds a minimal primitive for every outcome class and is the pattern for such a test. {spi-test}/PrimitiveContractTest.java[`PrimitiveContractTest`] runs them through the contract, {spi-test}/PrimitiveRegistryTest.java[`PrimitiveRegistryTest`] holds one malformed primitive per refusal, and {spi-test}/SpiVocabularyTest.java[`SpiVocabularyTest`] pins the constants of the closed enums.

A new validator, or a new rule of an existing one:

. Add a public `RULE_*` constant with the key and a Javadoc sentence that states the rule.
. Return a `ContentViolation` with the key, the line and a message that quotes the offending content. Return violations in the order of their lines.
. Add an accepted text and, for the new key, a rejected text that breaks only that rule, to the test of the validator: {spi-test}/validation/ConventionalCommitValidatorTest.java[`ConventionalCommitValidatorTest`], {spi-test}/validation/AsciiDocValidatorTest.java[`AsciiDocValidatorTest`], {spi-test}/validation/OutlineValidatorTest.java[`OutlineValidatorTest`].
