== The Packages
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5], link:../Requirements.adoc#PM-WF-16[PM-WF-16], link:../Requirements.adoc#PM-TEST-3[PM-TEST-3]_

The workflow language lives in the module `pm-workflow` of https://github.com/plan-marshall/pm-mcp-core[`pm-mcp-core`], in three packages. It uses `pm-core` for `OutcomeClass` and the primitive SPI (`PrimitiveRegistry`, `Primitive`, `FreeParam`, `PrimitiveOutcome`), and the streaming API of `jackson-core` for the instance header.

[#tree]
== The Tree
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5], link:../Requirements.adoc#PM-WF-16[PM-WF-16]_

A parsed unit is one https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/ast/WorkflowDefinition.java[`WorkflowDefinition`]: its id, version, scope (`WorkflowScope`), origin (`UnitOrigin`: `DEFAULT` for a unit compiled into the binary, `PROJECT` for a team's copy), the sub-workflow parameters (`ParamDecl`) and result schema, the optional instance header, the `declare` lines (`CallValue` by name) and `decide` lines (`DecisionDeclaration` by decision kind), the start state, the migrations (`StateMigration`) and the states (`StateNode` by id).

* *States*: A `StateNode` carries its phase, an optional terminal outcome (`TerminalOutcome`, with the `OutcomeClass` of `pm-core`), optional `skill` and `facts` clauses, and exactly one `StateBehavior`: `InteractiveLinks`, `AutoStep`, `JobStep` (with `composite` for a `composite_job`), `ModelJob` (a `job llm` task state with its role, fan-out or role-list primitive, `ask` flag and consulted roles), `SubWorkflowCall` (with its bound `CallValue` arguments), `QuestionWait` or `TerminalState`.
* *Links and guards*: A `LinkSpec` has its relation and form (`LinkRelation`, `LinkForm`; every relation knows its allowed forms and its default form), its free parameters (`ParamSpec` with a `ParamType`: `Text`, `Int`, `EnumOf`, `SchemaRef`, `ListOf`), an optional `GuardSpec` (a `GuardExpr` and the configuration keys it depends on), its action (`LinkAction.ExecutePrimitive`) and its transitions.
* *Transitions*: An `OutcomeTransition` routes an outcome to a target state, with an optional `ResultGuard` and the `StepCompletion` clauses it settles.
* *Also in the package*: `CallFrame`, one frame of a scope's call stack, and `GuardResult` (`Held`, `NotHeld`, `CouldNotEvaluate(reason)`); the parser produces neither, they are the types the engine will use.

Rules every record follows:

* *Immutable*: a record copies every list and map it is given in its compact constructor, so changing the caller's collection afterwards changes nothing, and the accessors return collections that refuse every change.
* *Declaration order*: a map keyed by id (`states`, `declarations`, `decisions`, `partVersions`, `derivedFrom`, the call bindings, the bound arguments of a frame) keeps the order in which its entries were declared: it is an unmodifiable view of a `LinkedHashMap` copy, never `Map.copyOf`. The printer relies on it.
* *Closed hierarchies*: every sealed interface lists its variants as nested records, so a `switch` over them needs no `default`, and adding a variant breaks every such `switch` at compile time.
* *Source locations*: every node the parser reads from a source carries a `SourceLocation` (resource, line, column); two trees are compared structurally only after their locations are stripped.
* *No validation*: a record takes what it is given; bounds, reachability and every other rule of the specification belong to the static verification.

[#parsing]
== Parsing
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5], link:../Requirements.adoc#PM-WF-16[PM-WF-16]_

`WorkflowParser.parse(resourceName, source, origin)` reads one unit and returns a https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/dsl/ParseResult.java[`ParseResult`]: `Parsed` with the `WorkflowDefinition`, or `Refused` with one `Diagnostic` (rule, resource name, line, column, message). A refusal is a value; no exception leaves `parse`, and only a `null` argument throws. The origin is the caller's, because the parser cannot know where a text came from.

* *Lexer*: `WorkflowLexer` cuts the source into lines, drops a comment from `#` to the end of its line, ignores indentation and blank lines, and gives every token its 1-based line and column. A word is an `INT` when it is all digits, an `IDENT` when it is lower case and starts with a letter, an `ENUM_VALUE` when it starts with a letter and contains an upper-case one, and `INVALID` otherwise; `->` ends a word, so `done->next` is three tokens. The JSON of an `instance` line stays one token, so a `#` inside it is no comment. The lexer never refuses; the parser refuses an `INVALID` token where it stands.
* *Parser*: a recursive descent over the grammar: the header, the optional `instance` line, the `scope` clause with the `param` and `result` declarations of a sub-workflow, the `declare` and `decide` lines, `start`, `migrate`, and every state form with its links, guards, transitions, result guards and step completions. A `link` without a form takes `LinkRelation.defaultForm()`. Guards bind `not` before `and` before `or`; a guard nested deeper than 32 parentheses is refused, which bounds the recursion.
* *Refusals*: the first refusal wins, and its `RefusalRule` is one of `STRUCTURE` (the source does not follow the grammar), `RESERVED_KEYWORD`, `MISSING_SCOPE` (a unit without a `scope` clause), `DUPLICATE_ID` (a state, a `declare` name, a decision kind, or a parameter declared twice in the file, including a sub-workflow parameter, a call argument and a link parameter) and `INSTANCE_HEADER`.
* *Reserved keywords only where the grammar names them*: a reserved keyword is refused as an outcome name, a parameter name, an entity kind, a role name, or a segment of a state, primitive or configuration key identifier. Everywhere else the positional vocabularies stay usable: `link retry retry [noop]` and `plan.allocate-remediation-tasks` parse. The rule also binds the unit id, which is a state id: no segment of a unit id may be a reserved keyword.
* *What the parser leaves to later stages*: identifier length bounds and every verification rule, the merge of a multi-file unit (`partVersions` and `derivedFrom` stay empty; a `derived_from` in the header is read and checked, not recorded), and the refusal of an `instance` line in a project unit.

[#instance-header]
== Reading the Instance Header
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5]_

The `instance` line of a plan instance version is one line of JSON. `InstanceHeaderReader` reads it with the streaming `JsonParser` of `jackson-core` into https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/ast/InstanceHeader.java[`InstanceHeader`] (`planId`, `version`, `event`, `inputs`, and the JSON exactly as read) with its https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/ast/InstanceInputs.java[`InstanceInputs`]: the configuration hash, the template and sub-unit references (`UnitRef`: unit, optional file, digest, origin), the composition rule reference (`CompositionRules`: revision, digest), the plan facts digest, and the three optional digests, empty when the member is absent or `null`.

The reader checks the structure of the https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/doc/developer/workflow-plan.adoc#_the_header_model[plan instance header]: the required members and their JSON types, and no member named twice in any object; it ignores members it does not model, which stay in the JSON. A defect is a refusal `INSTANCE_HEADER` whose message names the member, for example `member 'inputs.templates[0].digest' of the instance header must be a string`; a header without `inputs`, such as one that carries a flat `input_digests` map, is refused. The other checks of the schema (constants, enumerations, patterns, members it does not allow) are made by `HeaderSchemaCheck` of the plan instance composition. A `jackson-core` exception is mapped to the refusal and never rethrown.

[#printing]
== Printing and the Round Trip
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5]_

`WorkflowPrinter.print(definition)` writes a tree back as canonical source: the header, the `instance` line, the scope clause with its declarations, the `declare`, `decide`, `start` and `migrate` lines, and the states in declaration order, each after a blank line, with their clauses indented by nesting. Every link names its form, even the default one, and a guard carries exactly the parentheses its precedence needs (`not (not x)` for a doubly negated operand, because the grammar has no `not not`). A range of a `text` or `int` type is printed only when both bounds are present. The printer checks nothing and prints no data the parser of one file does not record (part versions, `derived_from`).

The round trip is the contract: parsing the printed source gives the same tree, source locations aside, and printing that tree again gives the same text.

[#verification]
== Static Verification
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5], link:../Requirements.adoc#PM-TEST-3[PM-TEST-3]_

https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/verify/WorkflowValidator.java[`WorkflowValidator`] checks one parsed `WorkflowDefinition`. It reads nothing on its own: its constructor takes the `PrimitiveRegistry` of the primitives a unit may name and the released state names of earlier releases, the baseline, in the order they are reported. `verify(definition)` returns a https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/verify/VerificationResult.java[`VerificationResult`]: every https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/verify/Violation.java[`Violation`] of the unit (the rule, the state, its `SourceLocation` and a message naming the primitive, outcome, parameter, link or released name concerned), and `passed()` when there is none. A violation is a value; only a `null` argument throws.

The checks are the constants of https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/verify/VerificationRule.java[`VerificationRule`], the only source of the rule vocabulary; each constant carries the number of the specification rule it implements a part of. What each check does:

* *Primitive binding*: the primitive of every `auto`, `job` and `composite_job` state, of every `facts` clause, of the `do` of every declared link (of a link state and of a question state) and of every `predicate:` atom of a link's guard is registered.
* *Parameter equivalence*: the free parameters of a link whose primitive is registered equal the `@FreeParam` components of the primitive's parameter record: the same names, nothing missing and nothing extra, the type `text`, and the same length bounds, an absent range counting as `0..Integer.MAX_VALUE`. Optionality is not compared, because `@FreeParam` declares none.
* *Outcome coverage*: the transitions of every `auto`, `job` and `composite_job` state and of every link whose primitive is registered route each wire name of the primitive's outcome enum exactly once. An outcome missing, unknown or routed twice is a violation; a job primitive's enum carries `cancelled`, so a job state needs no special case. A site whose primitive is not registered is left to primitive binding.
* *Reachability*: every state is reachable from the start state over every transition target.
* *Exit path*: every non-terminal state has a path to a terminal state; in a `workspace` unit every state has a path back to the start state instead.
* *Link identifiers*: the identifier patterns of the declared links of a state are unique, and none repeats the implicit `step_out` the engine renders on a link state of a sub-workflow.
* *Released states*: every name of the baseline is a state of the unit, or the old state of a `migrate` declaration whose target is a state. The violation names the released name and stands at its `migrate` line, or at the unit header when no `migrate` names it.

No check stops at the first violation. The result lists every violation, ordered by the declaration order of its state (released names after every state) and then by rule; violations of one state and rule keep the order they were found in.

The exemptions, each kept at its check:

* *Abort terminals*: `plan.aborted` and `epic.aborted` are entered by the operator's abort, which no unit declares, so they count as reachable although nothing targets them.
* *Implicit `step_out`*: a link state of a `subworkflow` unit has an exit no transition declares, so it counts as an exit of its own.
* *Default `lost`*: a task state (`job llm`) that declares no `lost` transition leaves through the engine's default route, so it counts as an exit too.
* *Workspace*: a `workspace` unit has no terminal state; its states must return to the start state.

Reachability is graph reachability: the tree knows the configuration keys a guard depends on, not the values they take, so configuration combinations are not enumerated, and no guard is evaluated. The other verification rules of the specification, among them the existence of every transition target, the unique state identifiers across the files of a unit, the `job llm` and question outcomes, and the role and skill checks, are not checked yet (link:https://github.com/plan-marshall/pm-mcp-core/blob/main/doc/specification/workflow-dsl/04-ast-node-model.adoc#static-verification-rules[Workflow DSL Specification § Static AST Verification Rules]).

[#fuzzer]
== Transition Fuzzer
_Requirements: link:../Requirements.adoc#PM-TEST-3[PM-TEST-3]_

https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/verify/TransitionFuzzer.java[`TransitionFuzzer`] walks a unit that passed `WorkflowValidator` and reports every reached non-terminal state none of whose exits holds under a drawn assignment of the guard atoms: a dead state that reachability over the graph cannot see.

* *Configuration*: https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/verify/FuzzConfiguration.java[`FuzzConfiguration`] holds the seed, the number of runs and the greatest number of steps of one run; a count that is not positive is refused with `IllegalArgumentException`.
* *Seed*: the generator is created from the seed with the fixed algorithm `L64X128MixRandom` of the JDK, so the same configuration over the same unit gives the same report.
* *Guard atoms*: each run draws one two-valued assignment over the atoms the guards of the unit name (`in_worktree`, `has_open_findings`, `all_tasks_completed`, and `predicate:<primitive_id>` for a predicate primitive), each once, in the order of their first occurrence: the states and their declared links in declaration order, each guard read from left to right. An atom no guard names is not drawn. The atoms of a guard come from one exhaustive switch over `GuardExpr` in `UnitGraph`, which the evaluation of a guard reads as well, so a new guard variant fails to compile there and what is drawn cannot diverge from what is looked up.
* *The walk*: a run starts at the start state and takes at most the configured number of steps. A declared link holds when it has no guard or its guard is true under the assignment. The transitions the engine takes on its own (of `auto`, `job`, `composite_job`, `job llm`, `call` and the resolution of a question) always hold, and so do the implicit `step_out` and the default `lost` route, which leave the unit. At a state without a holding exit the run records the dead state and stops; otherwise it takes one holding exit and one of its targets at random. A terminal state ends the run, and so does a target that is not a state of the unit.
* *The report*: https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/verify/FuzzReport.java[`FuzzReport`] holds the configuration, the number of runs executed and every dead state reached, each once with its first witness, in the order found; `foundDeadState()` tells whether there is one. A https://github.com/plan-marshall/pm-mcp-core/blob/main/pm-workflow/src/main/java/de/planmarshall/workflow/verify/DeadState.java[`DeadState`] names the state, its location, the assignment of the run that reached it and the number of that run, counted from 1.

The guards are evaluated two-valued over the drawn atoms; the engine's three-valued evaluation, the persisted sub-states, the condition overlays and the bound jobs are not modelled.

[#pitfalls]
== Pitfalls
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5]_

* *Fixtures are written for the test.* A test unit below `src/test/resources/dsl/` is written for the case it covers, never copied from a default unit of the product: model-facing content lives only in `plan-marshall-mcp`, and no artifact of `pm-mcp-core` may carry it.
* *The instance JSON is printed as read.* The header's digest must stay reproducible, so the printer writes `InstanceHeader.json()` verbatim and never re-serialises the parsed members. Code that builds a header must supply the canonical JSON itself.
* *Keep the order.* A new map component of a record must keep declaration order like the others; `Map.copyOf` would make the printer's output depend on hashing.
* *A new construct touches four places.* The record in `workflow.ast`, the parser, the printer, and a fixture with its expected tree; the round-trip tests fail until the printer writes what the parser reads.
* *Reserved words in names.* A name that reads naturally can be refused because one of its segments is reserved: a unit called `question.something` or a primitive `link.check` does not parse, and neither does a state id with the segment `start`; the test units name their start state `verify.entry`.
* *An exemption stays at its check.* The abort terminals are exempt from reachability, the implicit `step_out` and the default `lost` route count as exits, and a workspace unit returns to its start state; each exemption is written where its check runs, as a named constant or condition with its reason, never as a filter on the result, so a new check does not inherit an exemption it should not have.
* *One vocabulary for the rules.* A new check is a new constant of `VerificationRule`; no message, test or document names a rule by a string of its own.
* *Every check has a refusing fixture and a matched control.* A new check gets a fixture below `src/test/resources/verify/refused/` that plants exactly its defect and states it in a leading `# expect: <RULE> state <id> line <n>` comment, and the test is red before the check exists; the unit that uses every construct (`verify/passing/every-construct.pmwf`) must still pass, and every exemption has an inline control that passes with it and fails without it. The refusing fixtures are listed from the directory, never by hand.
* *The fuzzer needs a verified unit.* It walks only what the verifier accepted: a target that is not a state ends a run instead of failing it, so feeding it an unverified unit hides defects rather than finding them.

[#tests]
== Tests
_Requirements: link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5], link:../Requirements.adoc#PM-WF-16[PM-WF-16], link:../Requirements.adoc#PM-TEST-3[PM-TEST-3]_

* `AstNodeModelTest`: defensive copies, declaration order of the maps, closed hierarchies, the enum constants.
* `WorkflowLexerTest`: comments, blank lines, columns, token kinds, the instance-line JSON token.
* `WorkflowParserTest`: one expected tree per valid fixture (`dsl/valid/*.pmwf`), which together cover every construct, plus source locations, declaration order, default link forms and the positional vocabularies.
* `WorkflowParserRefusalTest`: every malformed fixture (`dsl/malformed/*.pmwf`) states its rule and line in a leading `# expect: <RULE> line <n>` comment and is refused with exactly that; inline units cover every further refusal, and the instance header reader is tested directly.
* `WorkflowPrinterTest`: the round trip and the fixed point over every valid fixture, canonical source that prints to itself, guard precedence, and the explicit link form.
* Helpers: `DslFixtures` reads and lists the fixtures; `AstWithoutLocations` strips the source locations so that two trees compare by structure.
* `WorkflowValidatorTest`: every refusing fixture (`verify/refused/*.pmwf`, one per check and two for outcome coverage, a missing and an unknown outcome) is refused with exactly the rule, state and line its leading comment expects, and together they cover every constant of `VerificationRule`; `verify/passing/every-construct.pmwf` passes every check; inline units cover the variants of each check, the controls of every exemption, and a unit with several defects that reports all of them in order.
* `TransitionFuzzerTest`: `verify/fuzz/planted-dead-state.pmwf` holds a link state whose only link is guarded by `in_worktree`; the fuzzer finds it with a fixed seed and names it with its location and an assignment with `in_worktree=false`. `verify/fuzz/control.pmwf` is the same unit without that guard, and the same seed reports nothing. Both pass the verifier and differ only in the planted guard, which the test asserts. Equal seeds give equal reports, other seeds find the planted state within the configured runs, only the atoms the guards name are drawn and in the order of their first occurrence, the witness run is counted from 1, a sub-workflow steps out of it, a run stops at the greatest number of steps, and an invalid configuration is refused.
* Helpers: `VerifyFixtures` reads, lists and parses the `verify/` fixtures; `TestPrimitives` holds the primitives the fixtures name and the registry the tests pass.
