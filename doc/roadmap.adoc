== Overview

This document defines the staged delivery sequence of *plan-marshall-mcp* (`PM-MCP`): what is delivered when, in which order, and how completion is verified, bridging the normative requirements in link:Requirements.adoc[Requirements] and the technical blueprints in link:Specification.adoc[Specification].

Project prefix: `PM-` | Status: Milestone 0 complete (the harness as worker and the technical verifications; results in the link:specification/evaluation.adoc[Evaluation Reference]; one item is blocked and carried in Milestone 14); next: Milestone 1 (`IN_PROGRESS`); Milestones 1 to 7, 11, and 13 hold items marked `[x]` or `[~]` for what the code of Milestone 0 Part B covers


1. *Foundation (Milestones 0–4)*: Verification first, the repositories and the module structure with the four native binaries, the always-on daemon with the worker relay `pm-mcp` and the terminal client `pm-operator`, the core DSL with the state stores, enrolment, and the pending entries of starts, and the job runtime with the role workers.
2. *Native Core Stores & Services (Milestones 5–6)*: Differential-tested native stores, build server, CI jobs, token-lane credentials, domain descriptors, the configuration model, and the operator release verb.
3. *Hypermedia Workflow Phases (Milestones 7–12)*: Phase-by-phase build-out with every model step a role task (the machine's and the project's onboarding, `init` with the plan start from the terminal client, and the `claude` bundle -> `refine`/`outline` -> `plan`/`execute` -> `finalize` -> web access with the web app as the second client -> `epics`), closed by the release that opens the lifecycle gate for the client profiles shipped by then (`claude`).
4. *Platform Services & Client Distribution (Milestones 13–14)*: Warm LSP pool, upstream MCP proxy, dynamic skill serving, and the client bundles and worker measurements of the remaining hosts.
5. *macOS Release (Milestone 15)*: The macOS release build of the four binaries with signing and notarisation, the last item of this roadmap; until then macOS is served by a developer's own native build.

Milestone 0 holds every verification; its Part B built each verified technique in its target module, so the product code starts there. An item of a later milestone that this code covers completely is marked `[x]` in its milestone; one it covers in part is marked `[~]` and states what is present and what remains, so that it can be finished from this document.

Items name deliverables and link their specification; the linked sections are authoritative, and the roadmap never restates their detail.

A milestone states what must exist for its exit; it does not state the order of work. The work is planned as work packages with their dependencies in `doc/plans/` of each code repository, one file per package with an index: link:https://github.com/plan-marshall/pm-mcp-clients/blob/main/doc/plans/README.adoc[`pm-mcp-clients`], link:https://github.com/plan-marshall/pm-mcp-core/blob/main/doc/plans/README.adoc[`pm-mcp-core`], and link:https://github.com/plan-marshall/plan-marshall-mcp/blob/main/doc/plans/README.adoc[`plan-marshall-mcp`]. A package names the milestone it serves and is ready when everything it depends on is done, whatever its milestone. The plans hold tasks only and link the requirements, specifications, and watch items here.

Every milestone takes the items of link:implementation-watch/cross-cutting.adoc[Cross-Cutting Implementation Watch] that are anchored to its specifications as mandatory watch input, beside the watch documents it names.

Every migration stage is a self-contained usable release (`PM-MIG-1`): prerequisites are pulled forward into the milestone that first needs them, and no stage relies on `plan-marshall` delivery (`PM-MIG-2`).

Improvements deliberately deferred (accepted limitations) are collected in link:later-improvements.adoc[Later Improvements] until they are scheduled here.

Artifacts are deployed only to the package registry of the GitHub organisation `plan-marshall`, never to Maven Central or another public registry (link:specification/module-structure.adoc#artifact-flow[Module Structure § Artifact Flow]); what is switched off and what still runs is recorded in link:roadmap/publishing.adoc[Publishing and Licensing State].
