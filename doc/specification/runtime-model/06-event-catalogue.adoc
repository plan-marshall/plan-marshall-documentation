[#event-catalogue]
== Event Catalogue
_See Requirement link:../../Requirements.adoc#PM-ARCH-11[PM-ARCH-11: The Operator's Two Clients & Their Contract]_

The closed catalogue of the events the runtime streams to the operator's clients (link:01-processes-and-transport.adoc#event-streams[Events per Scope]). Every event has a name of the event name grammar (link:../identifiers/02-registry-stores-to-web.adoc#id-event-name[Identifier Registry, Event Name]), one payload schema in `pm-api`, and the streams it is sent on; the envelope (`event`, `at`, `scope`, the SSE `id`) is that of link:01-processes-and-transport.adoc#event-streams[Events per Scope] and is not repeated below. A payload carries identifiers, states, counts, and message keys with their arguments; text of a model, a provider, or a harness travels only in the entries of a task's activity stream, marked untrusted. A new event, a new payload field, or a new stream for an event is a change of `pm-api`, checked by the mock runtime's load validation and the drift replay (link:05-mock-runtime.adoc[Mock Runtime]).

Streams: *R* the runtime-wide stream, *P* a plan's, *E* an epic's, *W* a project's workspace scope's, *M* the machine scope's, *N* an entry's, *Rep* the reports stream, *A* a task's activity stream.

=== Stream Control

[cols="2,1,3"]
|===
|Event |Streams |Payload

|`reset` |all |none: the events after the client's `Last-Event-ID` are no longer held, or the runtime started since; the client reads the scope's resources again
|`stream.closed` |all |`reason` (`device_revoked`, `device_expired` (the device's idle expiry, link:../cli-and-security/03-web-server.adoc#devices[CLI, Coordination & Security Specification, Devices in Both Clients]), `listener_closed`, `runtime_stopping`, `scope_ended`): the stream ends after it; `scope_ended` names the scope's successor stream where there is one (an entry's started scope, a project onboarding's workspace scope)
|===

=== Runtime, System & Cleanup

[cols="2,1,3"]
|===
|Event |Streams |Payload

|`runtime.draining` |R |`asked_by` (`operator`, `signal`, `service_manager`), `withdrawable`, `then` (`exit`, `restart`), `deadline_at` (link:02-startup-recovery-drain.adoc#runtime-lifecycle-operations[The Runtime's Lifecycle])
|`runtime.drain_withdrawn` |R |—
|`runtime.stopping` |R |`then`
|`runtime.upgrading` |R |`version`, `step` (`fetching`, `verifying`, `unpacking`, `switching`, `draining`), `withdrawable`
|`runtime.upgraded` |R |`from_version`, `to_version` (sent by the successor after its start)
|`runtime.upgrade_failed` |R |`version`, `reason` (message key), `rolled_back`
|`system.metrics` |R |the metrics that changed, each with its labels and value or `unavailable` (link:01-processes-and-transport.adoc#runtime-metrics[The Runtime's Metrics])
|`cleanup.job_opened` |R |`job_id`, the counts per kind, the space it frees (link:../timeouts/03-retention-host-config.adoc#cleanup[Timeouts & Budgets Specification, One Cleanup])
|`cleanup.decided` |R |`job_id`, `decision` (`delete`, `remind`, `ignore`), `remind_at`
|`cleanup.progress` |R |`job_id`, `done`, `failed`, `total`
|`cleanup.done` |R |`job_id`, `deleted`, `failed`, `kept`
|`device.paired`, `device.renamed`, `device.revoked` |R |`device_id`, `label`, `paired_from`; a pairing code never travels in an event (link:../cli-and-security/03-web-server.adoc#fresh-code[CLI, Coordination & Security Specification, A Fresh Code after a Redemption])
|`listener.changed` |R |`listener` (`loopback`, `lan`), `state` (`open`, `closed`, `port_occupied`), `port`
|`settings.changed` |R, M, W, P |`level` (`machine`, `project`, `plan`), the keys changed, the new `revision`, the channel
|===

=== Overview

[cols="2,1,3"]
|===
|Event |Streams |Payload

|`project.work_started`, `project.work_ended` |R |`project_id` (the project gained or lost running work)
|`project.changed` |R |`project_id`, the fields that changed (display name, readiness, released)
|`scope.started` |R, E |`kind` (`plan`, `epic`), `id`, `project_id`, `epic_id`, `title`
|`scope.ended` |R, E |`kind`, `id`, `outcome` or `terminal_reason`, `reason`
|`phase.changed` |R, P, E |`plan_id`, `phase`, `phase_entered_at`
|`activity.changed` |R, P, E |`plan_id`, `activity` (`running`, `pausing`, `paused`), the pause's `point`
|`needs_operator.changed` |R, P, E, W |`kind` and `id` of the summarized scope or project, the new summary (link:01-processes-and-transport.adoc#needs-operator[What Needs the Operator])
|`condition.raised`, `condition.cleared` |R, P, E, W |the scope, `condition`, `cleared_by` (`self`, `operator`)
|`hold.opened`, `hold.changed`, `hold.cleared` |R, P, E, W, N |the scope, `hold_id`, `kind`, `cleared_by` (`act`, `self`) (link:../state-catalogue/01-conventions-generic-conditions.adoc#holds[State Catalogue Specification, Holds and Their Acts])
|`epic.row_changed` |R, E |`epic_id`, `plan_id`, `status`, `waits_for` (`dependency`, `lock`, `scope`, `overlap`) with the plan it waits for
|`task.off_track` |R, P, E |`plan_id` or `epic_id`, `queue_task_id`, `signal`, `action` (link:../model-work/03-supervision-and-recycling.adoc#worker-off-track[Model Work Specification, A Worker Off Track])
|===

=== States, Process & Decisions

[cols="2,1,3"]
|===
|Event |Streams |Payload

|`state.entered`, `state.left` |P, E, W, M, N |`node_id`, `state_id`, the state's kind (`operator_wait` among them), `outcome` (on `left`); an operator wait entered tells a client to read the state's representation
|`subworkflow.called`, `subworkflow.returned` |P, E, W, M, N |`node_id`, the sub-workflow, `outcome` (on `returned`)
|`step.opened`, `step.closed` |P |`node_id`, `step_id`, `firing`, `outcome` (on `closed`)
|`instance.changed` |P |`instance_version`, the composition event (link:01-processes-and-transport.adoc#process-events[Events of the Process])
|`tokens.changed` |P, E |`total_tokens`, `tokens_in`, `tokens_out`, the coverage
|`progress.changed` |P, M, W, N |`done`, `of` (the onboarding's steps, a plan's tasks)
|`check.result` |M, W, N |`check_id`, `result` (`running`, `pass`, `fail`, `skipped`), `cause` and `fix` as message keys with their arguments
|`decision.opened`, `decision.changed`, `decision.answered`, `decision.closed` |P, E, W, M, N |the address `<scope_id>/<question_id>`, `revision`, `channel` (on `answered`), `closure` (on `closed`) (link:../model-work/06-envelopes-questions-deadlines.adoc#decision-structure[Model Work Specification, The Decision Structure])
|`source.added`, `source.removed`, `source.flagged` |N, E |`source_id`, the source kind
|`entry.started` |N |the started scope's `kind` and `id`; the stream then ends with `stream.closed`
|`entry.abandoned` |N |—
|`entry.moved` |N |`project_id`: the project onboarding's entry moved into the project's workspace scope at `project.enrol`
|`task.offered`, `task.ended` |P, E, W, M |`queue_task_id`, `role`, `outcome` (on `ended`)
|`job.started`, `job.ended` |P, E, W |`job_id`, `kind`, `fate` (on `ended`)
|`worker.started`, `worker.recycled`, `worker.replaced` |R |`job_id`, `role`, `harness`
|`epic.auto_changed` |E |`auto_start`
|`epic.register_changed` |E |`register` (`findings`, `watches`), the item's id
|`epic.decomposition_changed` |E |the draft's state
|===
